### Management Cluster vs Workload Clusters

[PLACEHOLDER: Explain the hub-spoke model]

**Management Cluster:**
- Runs k0rdent components
- Stores cluster definitions and state
- Orchestrates provisioning operations
- Typically runs on k0s

**Workload Clusters:**
- Run actual applications
- Can be any Kubernetes distribution
- Managed declaratively via CRDs

## 3. Core Components Deep Dive

### 3.1 k0rdent Cluster Manager (KCM)

**Purpose:** Deployment and lifecycle management of Kubernetes clusters

**Key Responsibilities:**
- Cluster provisioning across multiple infrastructure providers
- Day-2 operations: upgrades, scaling, repairs
- Template-based cluster definitions
- Credential management for cloud providers

**Key CRDs:**
- `Management` - Core configuration object
- `ClusterDeployment` - Defines a cluster to be provisioned
- `ClusterTemplate` - Reusable cluster configurations
- `Credential` - Cloud provider authentication
