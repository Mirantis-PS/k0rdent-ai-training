## 1. k0rdent Cluster Manager (KCM) - Deep Dive

### Architecture

```
┌────────────────────────────────────────────────────────┐
│                        KCM                              │
│  ┌──────────────────┐  ┌──────────────────────────┐    │
│  │  kcm-controller  │  │    Provider Controllers  │    │
│  │     manager      │  │  ┌─────┐ ┌─────┐ ┌────┐ │    │
│  │                  │  │  │CAPA │ │CAPZ │ │... │ │    │
│  │  - Management    │  │  └─────┘ └─────┘ └────┘ │    │
│  │  - Templates     │  └──────────────────────────┘    │
│  │  - Deployments   │                                  │
│  └──────────────────┘                                  │
│                                                        │
│  ┌──────────────────┐  ┌──────────────────────────┐    │
│  │   cert-manager   │  │      Flux Controllers    │    │
│  │                  │  │   (GitOps integration)   │    │
│  └──────────────────┘  └──────────────────────────┘    │
└────────────────────────────────────────────────────────┘
```

### Key Custom Resource Definitions (CRDs)

#### Management

The `Management` CRD is the central configuration object for k0rdent.

```yaml
apiVersion: k0rdent.mirantis.com/v1beta1
kind: Management
metadata:
  name: kcm
  namespace: kcm-system
spec:
  # [PLACEHOLDER: Key spec fields]
  providers:
    - name: aws
      # Provider configuration
  core:
    # Core component settings
```

**Key Fields:**
- `spec.providers` - List of enabled infrastructure providers
- `spec.core` - Core component configuration
- [PLACEHOLDER: Additional important fields]

#### ClusterTemplate

Templates define reusable cluster configurations.

```yaml
apiVersion: k0rdent.mirantis.com/v1beta1
kind: ClusterTemplate
metadata:
  name: aws-standalone-cp
  namespace: kcm-system
spec:
  # [PLACEHOLDER: Template structure]
  providers:
    infrastructure: aws
    bootstrap: k0s
    controlPlane: k0s
```

**Types of Templates:**
- Standalone Control Plane (single-node)
- Highly Available Control Plane (multi-node)
- Worker-only (join existing cluster)

#### ClusterDeployment

Represents an actual cluster to be provisioned.

```yaml
apiVersion: k0rdent.mirantis.com/v1beta1
kind: ClusterDeployment
metadata:
  name: my-workload-cluster
  namespace: my-tenant
spec:
  template: aws-standalone-cp
  credential: aws-creds
  config:
    region: us-east-1
    controlPlane:
      instanceType: t3.large
    # [PLACEHOLDER: Additional config options]
```

**Lifecycle States:**
- `Pending` - Waiting for prerequisites
- `Provisioning` - Infrastructure being created
- `Ready` - Cluster is operational
- `Deleting` - Tear-down in progress
- `Failed` - Error occurred

#### Credential

Stores cloud provider authentication.

```yaml
apiVersion: k0rdent.mirantis.com/v1beta1
kind: Credential
metadata:
  name: aws-creds
  namespace: kcm-system
spec:
  # References a Secret containing actual credentials
  identityRef:
    kind: Secret
    name: aws-credentials
    namespace: kcm-system
```

## 5. Controller Pattern

### How Controllers Work

k0rdent uses the Kubernetes controller pattern:

```
┌─────────────┐     ┌──────────────┐     ┌─────────────────┐
│  User       │     │  API Server  │     │   Controller    │
│  applies    │────▶│  stores      │────▶│   reconciles    │
│  manifest   │     │  object      │     │   desired state │
└─────────────┘     └──────────────┘     └─────────────────┘
                                                  │
                                                  ▼
                                         ┌─────────────────┐
                                         │ Infrastructure  │
                                         │ is provisioned  │
                                         └─────────────────┘
```

### Reconciliation Loop

1. Watch for changes to CRDs
2. Compare desired state vs actual state
3. Take action to reconcile differences
4. Update status on CRD
5. Repeat

## 6. Hands-on Exploration Commands

Use these commands to explore the components in your lab environment:

```bash
# List all k0rdent CRDs
kubectl get crds | grep k0rdent.mirantis.com

# Describe the Management object
kubectl describe management -n kcm-system

# View controller logs
kubectl logs -n kcm-system -l app.kubernetes.io/name=kcm -f

# List all templates
kubectl get clustertemplates -A -o wide

# Check provider status
kubectl get providers -n kcm-system
```
